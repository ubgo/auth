# github.com/ubgo/auth/plugin/oauth

Lets people sign in with Google, GitHub, Apple or any OpenID Connect issuer (Okta, Auth0, Keycloak, Entra ID, Zitadel), link those accounts to an existing user, sign in from a native app with the provider's ID token, sign out at the provider too, and optionally keep the provider's tokens for calling its API later.

## Install

```sh
go get github.com/ubgo/auth
```

The package is part of the core module `github.com/ubgo/auth`. It adds no dependency beyond the core's own (`github.com/ubgo/sqlb`, `golang.org/x/crypto`): provider calls use `net/http` and `encoding/json` from the standard library.

## Wire it

From [examples/oauth](../../examples/oauth/main.go):

```go
a, err := auth.New(
	auth.WithDB(db, sqlb.SQLiteDialect{}),
	auth.WithBaseURL(baseURL),
	auth.WithPlugins(
		email.New(email.Login(), email.Recover(), email.WithMailer(m)),
		password.New(),
		oauth.New(oauth.WithProviders(oauth.GitHub(os.Getenv("GITHUB_CLIENT_ID"), os.Getenv("GITHUB_CLIENT_SECRET")))),
	),
)
// ...
mux.Handle("/auth/", authhttp.Handler(a, authhttp.Prefix("/auth")))
```

The plugin works alone (it is a sign-in method by itself), but with the `email` plugin a provider that vouches for a verified address that is already a verified identity signs in to that account instead of creating a second one. Register `BaseURL + "/auth/oauth/<provider>/callback"` as the redirect URI at each provider.

`auth.New` fails when:

| Condition | Error |
|---|---|
| No provider passed | `ErrNoProviders`: "oauth: no providers" |
| A provider name does not match `auth.KindNamePattern` (`^[a-z][a-z0-9_]{0,30}$`) | "oauth: provider name %q must match ..." |
| Neither `auth.WithBaseURL` nor `oauth.CallbackURL` is set | `ErrNoCallbackURL`: "oauth: callback URLs need auth.WithBaseURL or oauth.CallbackURL" |
| `StoreTokens` got a key that is not [`auth.SealKeySize`](ds:block?id=sealkeysize-ks8du6jx) (32) bytes, or no key while `auth.WithSecret` is not set | `ErrBadTokenKey`: "oauth: StoreTokens needs a 32-byte key" |
| An `*OAuth2` lacks `AuthURL`, `TokenURL` (unless `GetToken` replaces the exchange), `ClientID` or a profile source (`FetchProfile`, or `IDToken.ProfileFromToken`), names an unknown `TokenAuth`, or is a `PublicClient` with a `ClientSecret` or `ClientSecretFunc` | `ErrProviderIncomplete`: "oauth: a provider needs AuthURL, TokenURL (or GetToken), ClientID, FetchProfile (or IDToken.ProfileFromToken) and a known TokenAuth (no secret for a PublicClient)" |
| An `*OIDCProvider` has a `Fallback` with some endpoint set but no `AuthURL`, `TokenURL` or `UserInfoURL` | `ErrFallbackIncomplete` |
| `AllowProviderInitiated` or `RestartProviderInitiated` names a provider that is not configured, both name the same one, or `AllowProviderInitiated` names an `*OAuth2` without an `IDToken` key set or a custom provider that is not an [`InitiatedExchanger`](ds:block?id=initiatedexchanger-v6kq2wnt) | `ErrProviderInitiatedConfig` |
| `SkipBrokenProviders` is set and every provider was left out | `ErrAllProvidersBroken`, wrapping each provider's reason |
| An `IDTokenConfig` has a `JWKSURL` but no `Issuers`, or `ProfileFromToken` without a `JWKSURL`; an `*OIDCProvider` with a hand-set `IDToken.JWKSURL` and no `Issuers` | `ErrIDTokenConfig`: "oauth: IDToken needs JWKSURL and Issuers (ProfileFromToken needs both)" |
| `ErrorURL` is not a path on this site or a trusted origin | `ErrBadReturnTo` (from `Init`) |
| Neither `auth.WithBaseURL` nor `oauth.PostLogoutURL` is set | `ErrNoCallbackURL` |

Apple has no userinfo endpoint, so its profile comes from the ID token the token endpoint returns, verified against Apple's keys (`IDToken.ProfileFromToken`); its client secret is a signed assertion, renewed every [day](ds:block?id=applesecretlifetime-c7ty2nwk) by `AppleClientSecret`. `oauth.Apple` requests no scopes, so its web flow yields the subject alone; the native flow (the id-token route) carries the email when the person shared it. [`oauth.AppleWithEmail`](ds:block?id=applewithemail-p7kd4mzq) requests `email` and `name`, which Apple answers by `response_mode=form_post`: a cross-site POST to the callback URL, which carries no `SameSite=Lax` flow cookie. The plugin therefore serves `POST` at every form-post provider's callback route as a relay that answers a redirect to the GET callback with the same `code`, `state` and `user` fields; the browser follows it as a top-level GET, the one cross-site request the flow cookie travels with, and the GET callback checks the state as always. The email comes from the ID token (a private relay address when the person hid theirs); the name comes from the `user` field Apple sends once, on first consent, read by [`oauth.ApplePostedUser`](ds:block?id=appleposteduser-w3nq8xkt) into `Profile.Name` (and into `Profile.Email`, unverified, only when the token had none). Register the same callback URL at Apple either way.

The presets' shapes follow each provider's documented API, pinned by fixture tests (`TestPresets_ProfileReaders`), not by calls to the live provider. A preset marks the email verified only when the provider's answer says so: Discord (`verified`), Dropbox, Atlassian, Kakao, Patreon, Zoom (`verified`), X (a confirmed address) and every OpenID Connect issuer with `email_verified` do; Facebook, Spotify, Figma, Naver, Kick, Linear, Cloudflare, Gumroad, HubSpot, Yandex and Microsoft (Graph's userinfo has no flag) do not, so their addresses never link to an existing user by themselves. `TrustedProviders("facebook", "linear")` trusts the ones you choose. Reddit returns no email. [`oauth.Presets`](ds:block?id=presets-j4wk8xqn) lists every route segment. Google One Tap and the Google mobile SDKs: set `g.IDToken = `[`oauth.GoogleIDTokens(audiences...)`](ds:block?id=googleidtokens-r8xq2mvd) on `oauth.Google` (keys at [`GoogleJWKSURL`](ds:block?id=googlejwksurl-h4tm9wqz), both Google issuers), or [`oauth.GoogleIDTokensFor(hostedDomain, …)`](ds:block?id=googleidtokensfor-k3wd7nqe) to refuse tokens outside one Workspace domain.

TikTok, Notion and WeChat run without PKCE (`NoPKCE`, below), because their web flows document none: the state stays single use and bound to the browser, and the client secret still guards the exchange, but a code stolen in transit could be injected into another browser's callback. VK ID runs PKCE. TikTok and WeChat send no email, so their users are created with no identity; Notion's and VK's addresses are unverified. WeChat's token endpoints are GETs that carry the app secret in the query string, as WeChat documents them; keep that host out of any proxy that logs URLs. VK ID's refresh grant also needs the `device_id`, which the plugin does not keep after the callback, so `Tokens` cannot refresh a VK token: request a fresh sign-in when it expires, or implement `oauth.Refresher` on a provider of your own. Sources: each provider's own documentation, read on 2026-10-06 (TikTok's through the Internet Archive, since developers.tiktok.com answers 503); the shapes are pinned by `TestTikTok_*`, `TestNotion_*`, `TestVK_*` and `TestWeChat_*`, not by live calls.

Dub, Instagram, Snapchat and Zoho were added on 2026-10-08. Dub and Snapchat run PKCE; Instagram runs without it (`NoPKCE`), as its documentation has none. None of Dub, Instagram or Snapchat sends an email, so their users are created with no identity; these presets do not invent an address such as `<id>@instagram.com` or `<id>@snapchat.com`, because a made-up address would look like a real one. Instagram's token answer is not RFC 6749 (documented wrapped in a `data` array, also seen flat), so the preset reads either; the token is the one-hour short-lived one ([`InstagramTokenLifetime`](ds:block?id=instagramtokenlifetime-p3i3wn6k)) and does not refresh, and `force_reauth` is an allowed per-request parameter. Dub's userinfo carries the authorized workspace, kept in `Profile.Claims["workspace"]`. Zoho signs in the users of the one data centre the client was registered in. Sources: each provider's documentation, read on 2026-10-08; pinned by `TestDub_*`, `TestInstagram_*`, `TestSnapchat_*`, `TestZohoRegions` and `TestPresetsP3_Constructors`, not by live calls.

Any other provider: fill an `*oauth.OAuth2` (`ID`, `ClientID`, `ClientSecret`, `AuthURL`, `TokenURL`, `Scopes`, `FetchProfile`), or implement the `oauth.Provider` interface (`Name`, `AuthCodeURL`, `Exchange`). Implementing `oauth.Refresher` enables token refresh in `Tokens`; implementing `oauth.Discoverer` makes the start operation call `Discover` first; implementing [`oauth.IDTokenVerifier`](ds:block?id=idtokenverifier-pq8r2vfn) gives the provider an id-token route and [`oauth.Logouter`](ds:block?id=logouter-x3nd8bqv) a logout route; [`oauth.ProfileFetcher`](ds:block?id=profilefetcher-m2kq8rtv) lets `Profile` read the provider's profile with stored tokens, [`oauth.Revoker`](ds:block?id=revoker-t7xn3pqw) lets unlink revoke them, and [`oauth.IssuerChecker`](ds:block?id=issuerchecker-z6tn3xkq) makes the callback require the RFC 9207 `iss`. `*OAuth2` and `*OIDCProvider` implement all seven, plus [`oauth.Labeler`](ds:block?id=labeler-c5wq8nxt) (the display name), [`oauth.Loader`](ds:block?id=loader-n7wk3xqt) (what `SkipBrokenProviders` loads at start) and [`oauth.InitiatedExchanger`](ds:block?id=initiatedexchanger-v6kq2wnt) (provider-initiated sign-in). Prove a provider of your own with the conformance kit [`oauthtest.Run`](ds:block?id=oauthtest-run-h4kw9qzt) ([oauthtest](oauthtest/)); to reuse a [goth](https://github.com/markbates/goth) provider instead, wrap it with [`authgoth.Wrap`](ds:block?id=authgoth-wrap-m7tq3xnv) from the separate module [contrib/goth](../../contrib/goth/). [`oauth.FormPoster`](ds:block?id=formposter-n2xk8wqm) (`*OAuth2` with `FormPost`) gets the POST relay at its callback route and [`oauth.PostedProfile`](ds:block?id=postedprofile-k4wn7xqt) (`*OAuth2` with `PostedUser`) is handed the callback's `user` field. GitHub's email comes from `/user/emails`, the address GitHub marks primary, with GitHub's own verified flag. Set `TokenAuth`, `AuthParams`, `TokenParams`, `OptionalScopes`, `TokenLifetime`, `IDToken`, `EndSessionURL` and `ClientSecretFunc` on an `*oauth.OAuth2` as the provider needs; a `Provider` of your own implements `oauth.ParamsProvider` too to accept `prompt`, `loginHint` and extra scopes per request.

A provider whose authorization URL depends on the request that starts the flow implements [`oauth.RequestAuthURLer`](ds:block?id=oauth-requestauthurler-3v9kq2wn): start then calls `AuthCodeURLForRequest(ctx, state, challenge, redirectURI, params)` with the request's context instead of `AuthCodeURL`, so the provider can read a header or the host with `auth.RequestHeader` and `auth.RequestHost`. Request parameters still need a `ParamsProvider`. `plugin/oauthproxy` uses it for its per-request skip header.

## Options

| Option | What it does | Default |
|---|---|---|
| `WithProviders(ps ...Provider)` | Adds providers; one start and one callback operation each | none (required) |
| `WithHTTPClient(hc *http.Client)` | Client for every provider call. Provider calls never follow a redirect ([`ErrRedirectRefused`](../../plugin/oauth/oauth.go), logged; the flow fails with `oauth.provider_failed`), so a misconfigured or hostile endpoint cannot bounce the server to an internal address; a client with no `CheckRedirect` of its own is used as a copy with that policy | `&http.Client{Timeout: DefaultHTTPTimeout}` (10s), refusing redirects |
| `WithStateTTL(d time.Duration)` | How long a user may spend at the provider before the callback is refused | [`DefaultStateTTL`](ds:block?id=defaultstatettl-zsf722py) (10 minutes) |
| [`StoreTokensWith(s)`](ds:block?id=storetokenswith-8vk2nq5d) | `StoreTokens` with the tokens sealed by an `auth.Sealer` (Vault transit, AWS KMS) instead of an in-memory key; wins over `auth.WithSealer`, loses to a `StoreTokens` key. A seal error fails the sign-in; an open error is returned by `Tokens` | off |
| `StoreTokens(key ...[]byte)` | Keeps each account's access and refresh token, sealed with AES-256-GCM under `key`, or with no key under the app's `auth.WithSealer` when set, else the keys derived from `auth.WithSecret` (label `auth.KeyLabelOAuthTokens`, current secret first, so a rotated secret still opens old tokens); read back with `Tokens` | off: provider tokens are never stored |
| `CallbackURL(fn func(provider string) string)` | The redirect URI sent to each provider | `BaseURL + DefaultMountPrefix + "/oauth/<provider>/callback"` ([`DefaultMountPrefix`](ds:block?id=defaultmountprefix-4xrrxrkb) is `/auth`) |
| `NoSignUp(providers ...string)` | Callbacks never create a user (for the named providers, or all when none is named): a linked account signs in, a verified address matching a verified identity links and signs in, a signed-in user may link; anything else is `ErrSignUpDisabled` | off: strangers get an account |
| `RequireVerifiedEmail()` | A sign-in or sign-up whose profile has no email or an unverified one is `ErrEmailUnverified`; link flows are unaffected | off: an unverified address creates an unverified identity and signs in |
| [`RequireEmail()`](ds:block?id=requireemail-6wq3nk8v) | A sign-in or sign-up whose profile has no email at all is `ErrEmailNotFound` (`oauth.email_not_found`), before anything is written; an unverified address is admitted; link flows are unaffected | off: a provider account without an email creates a user with no identity |

Start answers 302 to the provider and sets the flow cookie. Callback answers 302 to `returnTo` (default `/`) and, unless it was a link flow, issues a session. The id-token route answers the same `CallbackResult` as JSON with the session issued (a cookie, or `Set-Auth-Token` in bearer mode) and no redirect: it is for an app, not a browser following links; no provider tokens are stored on that path. The ID token is checked for signature (RS256, ES256 or EdDSA against the provider's key set, refetched for an unknown `kid` at most once a [minute](ds:block?id=jwksminrefresh-c2hx4rtw) and at least once a [day](ds:block?id=jwksmaxage-m7tq3pwd)), `iss`, `aud`, `exp` and `iat` (with [30 seconds](ds:block?id=idtokenleeway-vb6nz8kq) of leeway), and `nonce`: the claim must equal the request's nonce or its SHA-256 hex (Apple's native flow hashes it); a token with a nonce needs the request to carry one, and a request with a nonce needs the token to carry it. Logout ends the session here through the core's own sign-out, then answers 302 to the provider's end-session endpoint with `id_token_hint` (when `StoreTokens` kept one), `client_id` and `post_logout_redirect_uri` (the request's `returnTo`, else `PostLogoutURL`); a Go caller gets the URL in `LogoutResult`. Accounts are listed oldest first, and accounts linked in the same instant in id order, so every engine returns the same order. `CallbackResult` also reports `Created`, `Linked` and `SecondFactorRequired`. `Tokens` refreshes an access token that expires within [`RefreshMargin`](ds:block?id=refreshmargin-xnszv5aq) (1 minute) when the account has a refresh token and the provider is a `Refresher`. An API key is refused by unlink and accounts (`auth.ErrAPIKeyRefused`).
