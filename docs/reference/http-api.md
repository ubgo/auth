# HTTP API reference

Every route the library serves when every built-in plugin is wired, mounted at `/auth` as the examples do. This file is generated by `task docs:api` from the operation list `auth.New` builds; do not edit it by hand, `task check` fails when it is stale. An app serves only the routes of the plugins it wires, and the OAuth routes exist once per configured provider (here `google` and `github`). The same routes with their input and output schemas are in [`openapi.json`](openapi.json), an OpenAPI 3.1 document; an app serves its own with `authhttp.OpenAPI`.

Every mutation is a `POST` with a JSON body; every query is a `GET` with its input in the query string. A mutation sent with a session cookie must carry a trusted `Origin` header. The requirement column is what the request must have before the operation runs: `public` anyone, `signed_in` a session, `fresh_sign_in` a session created within the fresh window, `pending_second_factor` a session waiting for its second step. Errors come back as `{"error":{"code":…,"message":…}}` with the status of the code; the codes are listed in [errors](../concepts/errors.md).
