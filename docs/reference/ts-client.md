# TypeScript client reference

Every method of the prebuilt TypeScript client in [`clients/ts`](../../clients/ts/), the client `task docs:api` generates with every built-in plugin wired. This file is generated by `task docs:api` from the same operation list as the client (`authhttp.TypeScriptMethods`); do not edit it by hand, `task check` fails when it is stale. A client your app generates with `auth client ts` has the core's methods, the methods of the plugins your app wires, and your own plugins' methods, named by the same rule.

A plugin's methods exist on the client only when its factory is passed to `createAuthClient({ plugins: [...] })` (see [plugins](../client/plugins.md)). A method's name is the operation id after the plugin's prefix, in camelCase. The route is below the mount prefix the client's `baseURL` carries (`/auth` here). Every method resolves to `{ data, error }`: `data` has the output type, and the input type is the argument (it may be left out when it is `EmptyInput` or every field is optional). The types are declared in `client.ts`; the requirement column is the one the [HTTP API reference](http-api.md) explains.
