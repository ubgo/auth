# @ubgo/auth-client

A typed `fetch` client for the HTTP API of [github.com/ubgo/auth](../../README.md), generated from the library's operation list. Every operation is a method; its input and output types come from the Go types; error codes are a closed union; and a plugin's methods exist only when the plugin is passed to `createAuthClient`, so calling a plugin the server does not serve is a compile error. No dependencies.

Not published to npm: copy `src/`, or generate a client for your own app with `myapp auth client ts --out <dir>` (the `authcli` command), which also types your custom plugins and their error codes.

```ts
import { createAuthClient, password, twofactor } from "./auth/index.ts";

const auth = createAuthClient({ baseURL: "/auth", plugins: [password(), twofactor()] });
const { data, error } = await auth.password.signIn({ identifier: "ada@example.com", password: "…" });
if (error?.code === "password.invalid_credentials") showWrongPassword();
else if (data?.secondFactorRequired) askForCode(); // then auth.twofactor.verify({ code })
```

## Two things to know before you ship

- **Bearer mode clears the token on sign-out only.** `signOut()` and `signOutAll()` empty the `TokenStore` when accepted and when answered `auth.signed_out` (the session had already ended); other calls that answer `auth.signed_out` leave it, because a pending second factor answers that code too. Clear the store yourself when one does outside the code step ([Reference › Pitfalls](../../docs/client/reference.md#pitfalls)).
- **A runtime with no global `fetch` needs the `fetch` option.** Without it, `createAuthClient` throws an `Error` naming that option when the client is built.

## Layout

| Path | What it is |
|---|---|
| `src/client.ts` | Generated: one type per Go input and output, one operation table and plugin factory per plugin, `createAuthClient` |
| `src/runtime.ts` | The fetch runtime, the same for every app. Its source is `authhttp/tsclient/runtime.ts`, embedded in the generator |
| `src/error-codes.ts` | Every error code, the same file as `docs/reference/error-codes.ts` |
| `src/extensions.ts` | The hand-written plugins that are not one request each, `oauthPopup()` and `lastLoginMethod()`, the same for every app. Its source is `authhttp/tsclient/extensions.ts`, embedded in the generator |
| `src/index.ts` | Re-exports the four |
| `examples/*.ts` | Every snippet the guides show, type-checked: `quickstart.ts`, `spa.ts`, `bearer.ts`, `errors.ts`, `flows.ts`, `plugins.ts` (one typed call per plugin namespace), `plugin-popup.ts` (the popup sign-in), `hooks-and-extras.ts` (hooks, typed session extras, `keyValueTokenStore`, the last-login hint) and `options.ts` (`fetch`, per-call `headers`, `signal`, the helper types; it also runs without a server: `node examples/options.ts`) |
| `test/typecheck/bad.ts` | Mistakes that must not compile, each marked with the error it must fail with |
| `test/smoke.ts` | An end-to-end run against the `two-factor` example in both token modes |
| `test/runtime.ts` | The runtime and the hand-written plugins against a stub `fetch` and a fake popup window: token handling, hooks, session extras, `oauth_query`, the last-login hint, and every gate and failure of the popup sign-in |

Everything in `src/` is generated: edit `authhttp/typescript.go`, `authhttp/tsclient/runtime.ts` or `authhttp/tsclient/extensions.ts`, never these files.

## Tasks

| Command | What it does |
|---|---|
| `task docs:api` | Regenerates `src/` (with the OpenAPI document and the error-code lists) from every built-in plugin |
| `task ts:check` | `tsc` under `strict` (5.6 or later on `PATH`), then `ts:typecheck`; part of `task check`, which also fails when `src/` is stale |
| `task ts:typecheck` | Fails unless `test/typecheck/bad.ts` fails to compile on exactly its 9 marked lines, each with its marked error |
| `task ts:smoke` | Starts the `two-factor` example on port 8095 and runs `test/smoke.ts` against it with Node (22.18 or later, which runs `.ts` without a flag) |
